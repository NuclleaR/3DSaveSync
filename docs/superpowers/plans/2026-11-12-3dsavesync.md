# 3DSaveSync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CIA homebrew app for the owner's 3DS that, on launch, backs up save data + extdata of every installed game to Koofr over WebDAV as versioned full snapshots, and lets the owner download any version into Checkpoint's folders or delete chosen versions.

**Architecture:** Hardware-free logic lives in `source/core/` (portable C++23, no libctru) and is unit-tested on the PC with doctest; it talks to the outside world only through small interfaces (`HttpTransport`, `Dav`, `GameSource`, `FileSource`, `LocalFs`, `Hasher`). `source/platform/` implements those interfaces on the 3DS (libcurl + mbedTLS, FS/AM services, SD card), and `source/ui/` draws the approved screens with citro2d. Network work runs on a worker thread so the UI keeps drawing.

**Tech Stack:** C++23, devkitPro (devkitARM, libctru, citro2d), `3ds-curl` + `3ds-mbedtls`, `3ds-tinyxml2`, makerom + bannertool for the CIA, Make, doctest 2.4.11 for PC tests (PC side links Arch's `tinyxml2`).

**Spec:** `docs/superpowers/specs/2026-11-12-3dsavesync-design.md`

**Progress:** Tasks 1–10 done (checked below). Task 11 works on the console; the rest of its Step 5 is open. Tasks 12–15 built (owner, 2026-11-12: "do the whole plan, then we test the finished app"); their console checks are collected into Task 16. Per-task commits and every deviation from this plan are listed in "Execution log" at the end.

## Global Constraints

- Koofr WebDAV endpoint: `https://app.koofr.net/dav/Koofr`; HTTP Basic auth with Koofr email + app password; TLS 1.2 minimum (Koofr rejects TLS 1.1). The console's built-in `httpc`/`sslc` must not be used.
- Cloud root default `/3DSaveSync`, changeable in Settings.
- Checkpoint folders: `/3ds/Checkpoint/saves/` and `/3ds/Checkpoint/extdata/`; title folder `"0x%05X " + sanitized short description` with id `(u32)titleId >> 8`; version folder `"%04i%02i%02i-%02i%02i%02i"` local time.
- A version is a full snapshot: save data plus extdata (if the game has any), even when only one changed.
- The app never deletes or overwrites a complete version on its own. The only automatic deletion is cleanup of its own unfinished uploads (Task 7). Complete versions are deleted only from the Delete screen after confirmation.
- Game save data and extdata are opened read-only. The app writes only to its own save archive, to `/3ds/Checkpoint/...` during Restore, and to Koofr.
- Credentials never touch the SD card in plaintext; they live only in the app's own save-data archive.
- UI text is English. Top screen 400×240, bottom (touch) 320×240. Touch and D-pad/A/B both work. Screens follow `docs/superpowers/mockups-2026-11-12-screens.html`.
- `source/core/` must not include libctru headers, throw exceptions or use RTTI (the 3DS build uses `-fno-exceptions -fno-rtti`).
- Never commit without the owner's explicit go-ahead for that change. Commit messages carry no AI attribution (no `Co-Authored-By`, no "Generated with").
- Steps marked **Owner on console** are performed by the owner on the real 3DS; the executor prepares the build, then stops and waits for the owner's report.

## Review Focus

1. Console date/time is wrong → certificate check fails → the summary shows "Secure connection failed. Check the console's date and time." rather than a generic error (tests: Task 6 `describe`, Task 11 curl error mapping).
2. Wi-Fi off at launch → "No connection to Koofr. Check Wi-Fi.", nothing marked uploaded, the menu stays usable (test: Task 8 `network error on first game stops the run`).
3. Koofr storage full (HTTP 507) mid-run → run stops with "Koofr storage is full.", no half-uploaded version visible, leftovers cleaned on next launch (tests: Task 6 `507 maps to Quota`, Task 7 `failed upload leaves no complete version`, Task 8 `quota error stops the run`).
4. Game names with `:` `!` `.` or non-ASCII letters (e.g. "Kid Icarus: Uprising", "Pokémon Moon") → folder names identical to Checkpoint's and survive URL encoding and PROPFIND decoding (tests: Task 3 sanitize cases, Task 5 round trip).
5. App password revoked after setup → "Koofr rejected the login. Check email and app password in Settings.", app reaches the menu so Settings is reachable (tests: Task 6 `401 maps to Auth`, Task 8 `auth error stops the run`).

  - `std::string sanitizeName(std::string_view utf8);`: each of `.,!\/:?*"<>|` becomes a space, then trailing spaces are stripped (Checkpoint's `removeForbiddenCharacters`). Byte-wise on UTF-8 is correct because all of these are ASCII.
  - `std::string titleFolderName(uint64_t titleId, std::string_view sanitizedName);`: `"0x%05X "` of `((uint32_t)titleId) >> 8`, then the name.
  - `std::string displayNameFromFolder(std::string_view folder);`: drops a leading `0x` + 5 hex + space prefix; returns the input unchanged if the prefix is absent.
  - `struct LocalDateTime { int year, month, day, hour, minute, second; };`
  - `std::string versionName(const LocalDateTime& t);`: `"%04i%02i%02i-%02i%02i%02i"`.
  - `std::string uniqueName(const std::string& base, const std::vector<std::string>& taken);`: `base` if free, else the first free `base + "-2"`, `"-3"`, …
  - `uint32_t extdataIdFor(uint64_t titleId);`: default `((uint32_t)titleId) >> 8`; exceptions on the low 32 bits: `0x00055E00→0x055D`, `0x0011C400→0x11C5`, `0x00175E00→0x1648`, `0x00179600,0x00179800→0x1794`, `0x00179700,0x0017A800→0x1795`, `0x0012DD00,0x0012DE00→0x12DC`, `0x001B5100→0x1B50`.

`parsePropfind` uses TinyXML2 and matches elements by local name (`response`, `href`, `collection`, `getcontentlength`) whatever the namespace prefix. For each `href`: drop `scheme://host` if present, percent-decode, drop `basePath` (e.g. `/dav/Koofr`) from the front, drop the trailing `/`. The entry equal to `requestPath` (after the same normalisation) is the folder itself and is excluded. `name` is the last path segment. Malformed XML → `Error{Protocol}`.

```cpp
// http.hpp
struct BodySource { uint64_t size; std::function<std::expected<size_t, Error>(char* buf, size_t cap)> read; };
class BodySink { public: virtual ~BodySink() = default; virtual std::expected<void, Error> write(const char* data, size_t len) = 0; };
struct HttpRequest { std::string method; std::string url; std::vector<std::pair<std::string, std::string>> headers;
                     std::string textBody; std::optional<BodySource> streamBody; };
struct HttpResponse { int status = 0; std::string body; };
class HttpTransport { public: virtual ~HttpTransport() = default;
    // sink != nullptr and 2xx: body goes to sink; otherwise into HttpResponse::body. Transport failures: Network / Tls / Cancelled.
    virtual std::expected<HttpResponse, Error> send(const HttpRequest& req, BodySink* sink) = 0; };
// dav.hpp — paths are plain absolute paths like "/3DSaveSync/saves/0x0175E Pokémon Moon"
class Dav { public: virtual ~Dav() = default;
    virtual std::expected<std::vector<DavEntry>, Error> list(const std::string& path) = 0;   // missing → NotFound
    virtual std::expected<void, Error> makeDirs(const std::string& path) = 0;                 // creates each missing segment
    virtual std::expected<void, Error> put(const std::string& path, BodySource body) = 0;
    virtual std::expected<std::string, Error> getText(const std::string& path) = 0;
    virtual std::expected<void, Error> get(const std::string& path, BodySink& sink) = 0;
    virtual std::expected<void, Error> move(const std::string& from, const std::string& to) = 0; // destination exists → Conflict
    virtual std::expected<void, Error> remove(const std::string& path) = 0; };               // missing → success
// webdav_client.hpp
inline constexpr const char* PROPFIND_BODY = R"(<?xml version="1.0" encoding="utf-8"?><d:propfind xmlns:d="DAV:"><d:prop><d:resourcetype/><d:getcontentlength/></d:prop></d:propfind>)";
class WebDavClient : public Dav { public: WebDavClient(HttpTransport& t, std::string baseUrl); /* Dav overrides */ };
// error.hpp
std::string describe(const Error& e);
bool isFatal(const Error& e);   // Network, Tls, Auth, Quota, Cancelled
```

Request shapes: URL = `baseUrl + encodePath(path)`; `basePath` for `parsePropfind` = path component of `baseUrl` (`/dav/Koofr`). PROPFIND: header `Depth: 1`, `Content-Type: application/xml`, body `PROPFIND_BODY`. MOVE: `Destination: baseUrl + encodePath(to)`, `Overwrite: F`. `makeDirs` sends MKCOL for every prefix segment; the "already exists" code from the Task 2 probe results counts as success. Status mapping, any method: 2xx → ok; 401/403 → Auth; 404 → NotFound (except DELETE, where it is success); 409 → Conflict; 412 → Conflict; 507 → Quota; 5xx → Server; anything else → Protocol with the code in `detail`.

`describe` texts (exact): Network `"No connection to Koofr. Check Wi-Fi."`; Tls `"Secure connection failed. Check the console's date and time."`; Auth `"Koofr rejected the login. Check email and app password in Settings."`; Quota `"Koofr storage is full."`; Cancelled `"Cancelled."`; others `"Koofr error: " + detail`.

A version is complete exactly when its `.manifest` exists under `root/manifests/<title>/`. `uploadVersion`, in order:
1. PUT every Save file to `incomingDir/saves/<path>` and every Extdata file to `incomingDir/extdata/<path>` (`makeDirs` for parents), checking `cancel` before each file (→ `Error{Cancelled}`).
2. PUT the serialized manifest to `incomingDir/<version>.manifest`.
3. `makeDirs(root/saves/<title>)`, MOVE `incomingDir/saves` → `savesDir`.
4. If the manifest has Extdata: `makeDirs(root/extdata/<title>)`, MOVE `incomingDir/extdata` → `extdataDir`.
5. `makeDirs(root/manifests/<title>)`, MOVE the manifest → `manifestPath`. This is the completion point.
6. `remove(incomingDir)`.

`cleanupIncomplete`: for every `root/.incoming/<title>/<version>`: if `manifestPath(title, version)` does not exist, `remove` `savesDir` and `extdataDir` of that same title/version (partial moves of this interrupted upload); then `remove` the incoming folder. It never touches a saves/extdata folder that has no `.incoming` counterpart, and never one whose manifest exists. If listing `.incoming` fails with anything but NotFound, it returns the error and deletes nothing.

`deleteVersion` removes `savesDir`, then `extdataDir`, then `manifestPath` last, so a failed delete stays visible and can be retried. `download` GETs `savesDir/<path>` or `extdataDir/<path>` according to `f.part`.
